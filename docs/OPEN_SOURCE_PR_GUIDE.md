# First meaningful open-source PR: a practical path

Pick a project you already use, ideally in your ML stack: scikit-learn, pandas, Hugging Face (transformers/datasets), LangChain, FastAPI, or a recommender library such as Surprise, implicit, LightFM or RecBole.

1. **Read CONTRIBUTING.md** and look for issues labelled `good first issue`, `help wanted` or `documentation`.
2. **Start where you have expertise**: recommender metrics, docs for evaluation functions, a missing edge case in a ranking metric, a failing test, an unclear example.
3. **Comment on the issue first** ("I'd like to work on this; my plan is ...") and wait for a maintainer nod.
4. **Fork, branch, small change**, with tests and docs updated; follow their linting and commit style.
5. **Open a PR** that links the issue, explains what and why, and shows test output.
6. **Respond to review promptly.** Collaboration with maintainers is the actual evidence.

Quality over count: one merged, well-discussed PR beats five typo fixes. Keep the PR link and a one-line summary for your portfolio.
